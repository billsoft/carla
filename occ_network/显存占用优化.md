## 直接回答

**TBPTT 显存优化是有成熟方案的，不需要裁剪网络结构。**

业界主流方案是 **Gradient Checkpointing for Temporal Dimension**（时序维度梯度检查点），核心思想：

> **历史帧不存激活值，backward 时重新 forward 计算**

### 显存消耗分析

你当前的问题根源：

```
Window=3 时的显存占用：

当前帧:  Encoder激活 + BEV激活 + 3D体素激活 ≈ 2GB
历史帧1: Encoder激活 + BEV激活 + 3D体素激活 ≈ 2GB  
历史帧2: Encoder激活 + BEV激活 + 3D体素激活 ≈ 2GB
                                              ────
                                      总计 ≈ 6GB (×3倍)

问题：历史帧的激活值占了 2/3 的显存！
```

### 优化方案对比

| 方案 | 原理 | 显存节省 | 计算开销 | 实现难度 |
|------|------|----------|----------|----------|
| **时序梯度检查点** | 历史帧激活不存，backward重算 | 50-60% | +30% | 中等 |
| 历史帧特征压缩 | 历史BEV用FP16/降采样存储 | 30-40% | +5% | 简单 |
| 分阶段TBPTT | 只对Temporal模块做TBPTT | 40-50% | 0% | 简单 |
| 可逆网络 | 从输出反算输入 | 70-80% | +50% | 复杂 |

**推荐组合**：时序梯度检查点 + 历史帧特征压缩

## 方案一：时序梯度检查点（主推）

### 原理图解

```
正常 TBPTT (显存爆炸):
  帧0: [Encoder激活][BEV激活][3D激活] ← 全部存储
  帧1: [Encoder激活][BEV激活][3D激活] ← 全部存储  
  帧2: [Encoder激活][BEV激活][3D激活] ← 全部存储
  backward: 直接用存储的激活计算梯度

时序梯度检查点 (显存优化):
  帧0: [   只存输入   ] ← 不存中间激活
  帧1: [   只存输入   ] ← 不存中间激活
  帧2: [Encoder激活][BEV激活][3D激活] ← 当前帧正常存储
  backward: 
    计算帧2梯度 (直接用)
    重新forward帧1 → 计算帧1梯度
    重新forward帧0 → 计算帧0梯度
```

### 实现代码

**修改 `train_tbptt.py` 的训练循环**：

```python
# 在 train_tbptt.py 中添加
from torch.utils.checkpoint import checkpoint

def forward_with_checkpoint(model, images, ego_motion, ego_pose, timestamp, scene_id, 
                            intrinsics, extrinsics, use_checkpoint=False):
    """
    带梯度检查点的前向传播
    use_checkpoint=True 时不存储中间激活，backward时重算
    """
    if not use_checkpoint:
        return model(images, ego_motion, ego_pose, timestamp, scene_id, intrinsics, extrinsics)
    
    # 使用 checkpoint 包装 forward
    # 注意：checkpoint 要求输入必须 requires_grad
    images = images.requires_grad_(True)
    
    def forward_fn(img):
        return model(img, ego_motion, ego_pose, timestamp, scene_id, intrinsics, extrinsics)
    
    # checkpoint 不存储中间激活，backward时重新forward
    outputs = checkpoint(forward_fn, images, use_reentrant=False)
    return outputs


def train_one_epoch_tbptt_optimized(model, loader, optimizer, scaler, loss_fn, 
                                     epoch, config, tbptt_window=3):
    """
    显存优化版 TBPTT 训练
    
    核心优化：历史帧使用梯度检查点，不存储中间激活
    """
    model.train()
    total_loss = 0
    device = next(model.parameters()).device
    
    prefetcher = FP16DataPrefetcher(loader, device)
    batch = prefetcher.next()
    
    step = 0
    window_step = 0
    accumulated_loss = torch.tensor(0.0, device=device)
    
    # 🔑 存储窗口内的输入（而不是激活）
    window_inputs = []
    
    while batch is not None:
        # 存储当前 batch 的输入（显存很小）
        window_inputs.append({
            'images': batch['images'],  # 只存输入
            'ego_motion': batch.get('ego_motion'),
            'ego_pose': batch.get('ego_pose'),
            'timestamp': batch.get('timestamp'),
            'scene_id': batch.get('scene_id'),
            'intrinsics': batch.get('intrinsics'),
            'extrinsics': batch.get('extrinsics'),
            'targets': {k: v for k, v in batch.items() if k not in 
                       ['images', 'ego_motion', 'ego_pose', 'timestamp', 
                        'scene_id', 'intrinsics', 'extrinsics']}
        })
        window_step += 1
        
        # 到达窗口边界
        if window_step >= tbptt_window:
            # 🔑 重新 forward 所有帧，使用 checkpoint
            model.reset_temporal()  # 重置时序状态
            
            with autocast(enabled=config.use_amp):
                for i, inp in enumerate(window_inputs):
                    is_last = (i == len(window_inputs) - 1)
                    
                    # 历史帧用 checkpoint（不存激活）
                    # 最后一帧正常（需要存激活计算loss）
                    outputs = forward_with_checkpoint(
                        model,
                        inp['images'],
                        inp['ego_motion'],
                        inp['ego_pose'],
                        inp['timestamp'],
                        inp['scene_id'],
                        inp['intrinsics'],
                        inp['extrinsics'],
                        use_checkpoint=(not is_last)  # 只有最后帧不用checkpoint
                    )
                    
                    losses = loss_fn(outputs, inp['targets'])
                    accumulated_loss = accumulated_loss + losses['total']
                    total_loss += losses['total'].item()
            
            # Backward + Step
            if config.use_amp:
                scaler.scale(accumulated_loss).backward()
                scaler.unscale_(optimizer)
                nn.utils.clip_grad_norm_(model.parameters(), config.grad_clip)
                scaler.step(optimizer)
                scaler.update()
            else:
                accumulated_loss.backward()
                nn.utils.clip_grad_norm_(model.parameters(), config.grad_clip)
                optimizer.step()
            
            optimizer.zero_grad()
            detach_temporal_history(model)
            
            # 重置窗口
            accumulated_loss = torch.tensor(0.0, device=device)
            window_inputs = []
            window_step = 0
        
        step += 1
        batch = prefetcher.next()
    
    return total_loss / max(step, 1)
```

### 显存对比

```
优化前 (window=3):
  帧0激活: 2GB
  帧1激活: 2GB  
  帧2激活: 2GB
  总计: 6GB

优化后 (window=3 + checkpoint):
  帧0输入: 0.1GB (只存图片)
  帧1输入: 0.1GB
  帧2激活: 2GB (最后帧正常存)
  总计: 2.2GB (节省 63%!)

代价: 计算时间 +30% (历史帧需要重新forward)
```

## 方案二：历史帧特征压缩（简单有效）

### 原理

历史帧的特征精度不需要和当前帧一样高。

```python
# 在 temporal.py 的 _update_history 中添加压缩逻辑

def _update_history_compressed(self, bev: torch.Tensor, pose, timestamp, scene_id):
    """
    压缩存储历史帧
    """
    # 🔑 历史帧降采样 (128→64) 并转 FP16
    bev_compressed = F.interpolate(
        bev.float(), 
        size=(64, 64),  # 降采样一半
        mode='bilinear', 
        align_corners=False
    ).half()  # 转 FP16
    
    self.history_bevs.append(bev_compressed)
    # ...
    
def forward(self, current_bev, ...):
    # 使用时上采样回来
    aligned_bevs = [current_bev]
    for hist_bev in self.history_bevs:
        # 上采样回原尺寸
        hist_bev_full = F.interpolate(
            hist_bev.float(),
            size=(self.bev_h, self.bev_w),
            mode='bilinear',
            align_corners=False
        ).to(current_bev.dtype)
        
        aligned = self.motion_comp(hist_bev_full, ...)
        aligned_bevs.append(aligned)
    # ...
```

### 显存节省

```
原始: 128×128×192×FP32 = 12.6MB/帧
压缩: 64×64×192×FP16 = 1.6MB/帧 (节省 87%!)
```

## 方案三：分阶段 TBPTT（推荐入门）

### 原理

不是所有模块都需要 TBPTT，只对收益最大的 Temporal Fusion 做。

```
完整 TBPTT (显存大):
  历史帧: Encoder → BEV → Temporal → 3D (全程保留梯度)
                                        ↓
  当前帧: Encoder → BEV → Temporal → 3D → Loss
                            ↑
                    梯度回传到 Encoder

分阶段 TBPTT (显存小):
  历史帧: Encoder → BEV (detach) → Temporal (保留梯度)
                                        ↓
  当前帧: Encoder → BEV → Temporal → 3D → Loss
                           ↑
                  只回传到 Temporal，不回传到 Encoder
```

### 实现

修改 `occ_net.py` 的 forward：

```python
def forward(self, images, ego_motion=None, ego_pose=None, 
            timestamp=None, scene_id=None, intrinsics=None, extrinsics=None,
            tbptt_encoder_detach=True):  # 🔑 新增参数
    """
    tbptt_encoder_detach=True: 历史帧的 Encoder 输出 detach
                               只有 Temporal 模块参与 TBPTT
    """
    # ... Encoder ...
    encoded_tokens = self.encoder(camera_tokens, spatial_shape, self.camera_pe)
    
    # ... Fusion ...
    if self.use_depth_aware_fusion:
        fused_tokens, depth_logits, depth_pred = self.depth_fusion(...)
        
        # 🔑 如果是 TBPTT 模式，这里 detach
        # 这样 Encoder 的梯度不会回传到历史帧
        # 但 Temporal 的梯度仍然会回传
        if tbptt_encoder_detach and self.training:
            fused_tokens = fused_tokens.detach().requires_grad_(True)
    
    # ... BEV Decoder ...
    bev_features = self.decoder(fused_tokens, spatial_shapes)
    
    # 🔑 Temporal Fusion 正常，不 detach
    # 这是 TBPTT 真正生效的地方
    bev_features = self.temporal(bev_features, ego_motion, ego_pose, timestamp, scene_id)
    
    # ... 后续 ...
```

### 显存对比

```
完整 TBPTT (window=3):
  显存 ≈ 6GB (爆)

分阶段 TBPTT (window=3):
  Encoder激活: 只存当前帧 ≈ 1.5GB
  BEV/Temporal: 存3帧 ≈ 0.5GB × 3 = 1.5GB
  3D体素: 只存当前帧 ≈ 2GB
  总计 ≈ 5GB (可接受)
```

## 推荐方案：组合使用

针对你的自动驾驶体素生成需求，推荐：

```
方案组合: 分阶段TBPTT + 历史帧压缩

优点:
1. 实现简单，改动小
2. 显存可控 (window=3 约 4-5GB)
3. 保留了 Temporal Fusion 的 TBPTT 收益（这是最重要的）
4. Encoder 虽然不 TBPTT，但通过 Depth Supervision 也能学到时序相关特征
```

### 最终修改清单

| 文件 | 修改 | 作用 |
|------|------|------|
| `occ_net.py` | forward 添加 `tbptt_encoder_detach` 参数 | 分阶段TBPTT |
| `temporal.py` | `_update_history` 添加压缩逻辑 | 历史帧压缩 |
| `train_tbptt.py` | 调用时传入 `tbptt_encoder_detach=True` | 启用分阶段 |

这样 **window=3 应该能稳定在 4-5GB**，不会爆显存，同时保留了 TBPTT 对动态物体检测的核心收益。
