# 位置编码优化方案：消除 Yaw 冗余编码

## 一、问题分析

### 1.1 当前位置编码架构

OccNetV3 使用**三层位置编码**：

```
原始特征 [B, N, dim]
    ↓
1️⃣ HyperbolicFOVEncoding (内参编码) - 视场角差异
    ↓ 变换Q, K向量长度
2️⃣ CameraRoPE (外参编码) - ⚠️ 仅编码 Yaw 偏航角
    ↓ 旋转Q, K向量方向
3️⃣ RayDirectionEncoding (射线编码) - ⚠️ 包含完整 6-DoF 旋转矩阵
    ↓ 相加到token
4️⃣ Attention注意力计算
```

### 1.2 冗余问题

**核心问题**：Yaw 偏航角被编码了**两次**！

| 编码层 | 文件位置 | Yaw 信息来源 | 编码方式 |
|-------|---------|------------|---------|
| **CameraRoPE** | `position_encoding.py:6-18` | `rotation[2]` | 旋转 Q,K 向量 |
| **RayDirectionEncoding** | `position_encoding.py:145-171` | Rz 旋转矩阵 | 射线方向转换 |

**代码证据**：

```python
# CameraRoPE 中提取 Yaw (line 42-43)
yaw_angles.append(cfg['rotation'][2] * math.pi / 180.0)  # rotation[2] = yaw

# RayDirectionEncoding 中使用 Yaw (line 150)
pitch, roll, yaw = [math.radians(r) for r in rotation]
Rz = torch.tensor([
    [math.cos(yaw), -math.sin(yaw), 0],
    [math.sin(yaw), math.cos(yaw), 0],
    [0, 0, 1]
], dtype=torch.float32)
```

### 1.3 信息维度对比

| 特性 | CameraRoPE | RayDirectionEncoding |
|-----|-----------|---------------------|
| **自由度** | 1-DoF (仅 Yaw) | 6-DoF (Pitch + Roll + Yaw + 内参) |
| **覆盖场景** | 仅水平旋转 | 减速带(Pitch)、斜坡(Roll)、转弯(Yaw) |
| **信息完整度** | ❌ 不完整 | ✅ 完整 |

### 1.4 冗余的负面影响

1. **参数浪费**：模型需要学习处理重复信息
2. **过拟合风险**：对 Yaw 角过度敏感
3. **设计不优雅**：两种编码方式作用重叠

---

## 二、优化方案

### 方案核心思想

> **保留 RayDirectionEncoding（6-DoF 完整几何先验），移除 CameraRoPE 中的 Yaw 编码**

RayDirectionEncoding 已经通过旋转矩阵完整编码了相机的 3D 朝向（包括 Pitch, Roll, Yaw），因此 CameraRoPE 中的 Yaw 编码是**完全冗余**的。

### 方案选项

#### 方案 A：完全移除 CameraRoPE（推荐）

**理由**：
- RayDirectionEncoding 已提供完整的 6-DoF 几何信息
- CameraRoPE 的 1-DoF Yaw 编码是其子集，完全冗余
- 简化架构，减少计算量

**修改文件**：
- `models/position_encoding.py`
- `models/attention.py`
- `models/encoder.py`

#### 方案 B：改造 CameraRoPE 编码其他信息

将 CameraRoPE 改为编码**帧间时序信息**或**相机 ID**，避免与 RayDirection 重叠。

**优点**：保留 RoPE 机制的相对位置编码能力
**缺点**：增加复杂度，需要额外设计

#### 3.2.1 `models/position_encoding.py`

**修改后的 `MultiCameraPositionEncoding`**：
```python
class MultiCameraPositionEncoding(nn.Module):
    """
    多相机位置编码（简化版）

    仅使用 HyperbolicFOVEncoding 进行视场角编码
    3D 方向编码交给 RayDirectionEncoding 处理
    """
    def __init__(self, dim: int, camera_configs: Dict, temperature: float = 10000.0):
        super().__init__()
        # 提取 FOV 列表
        fov_list = []
        for cam_name in sorted(camera_configs.keys(), key=lambda x: camera_configs[x]['id']):
            fov_list.append(camera_configs[cam_name]['fov'])

        # 仅保留 FOV 编码
        self.fov_encoding = HyperbolicFOVEncoding(dim, fov_list)

    def encode_qk_single_camera(self, q, k, camera_id):
        """对单个相机的 Q, K 应用 FOV 编码"""
        q_enc = self.fov_encoding(q, camera_id)
        k_enc = self.fov_encoding(k, camera_id)
        return q_enc, k_enc
```

## 四、修改后的架构

### 4.1 新的位置编码流程

```
原始特征 [B, N, dim]
    ↓
1️⃣ HyperbolicFOVEncoding (内参编码) - 视场角差异
    ↓ 变换Q, K向量长度
2️⃣ RayDirectionEncoding (几何编码) - 完整 6-DoF 相机朝向
    ↓ 相加到token（包含 Pitch, Roll, Yaw 信息）
3️⃣ Attention注意力计算
```

### 4.2 信息编码对比

| 方面 | 修改前 | 修改后 |
|-----|-------|-------|
| Yaw 编码次数 | 2次（冗余） | 1次（仅 RayDirection） |
| Pitch/Roll | 仅 RayDirection | 仅 RayDirection |
| FOV 差异 | HyperbolicFOV | HyperbolicFOV |
| 计算量 | 多一次 RoPE 旋转 | 减少 |
| 参数量 | 略多 | 略少 |

## 六、风险评估

### 6.1 低风险

- **移除冗余编码**：RayDirection 已包含完整信息，移除 RoPE 不会丢失信息
- **FOV 编码保留**：内参差异编码保持不变

### 6.2 需要监控

- **Attention 权重分布**：移除 RoPE 后，跨相机注意力模式可能变化
- **收敛速度**：可能略有变化，但不应显著恶化

### 6.3 回滚计划

如果优化后性能显著下降，可以：
1. 恢复 CameraRoPE
2. 或改为方案 B（CameraRoPE 编码其他信息）
