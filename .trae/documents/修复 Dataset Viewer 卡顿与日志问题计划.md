# 修复 Dataset Viewer 卡顿与日志问题计划

根据您的反馈和代码对比分析，问题主要在于：
1.  **DNG 处理过重**: 8 张 12-bit DNG 同时解码非常消耗 CPU，导致 Flask 服务器阻塞，体素请求排队等待。
2.  **浏览器并发限制**: 浏览器对同一域名的并发连接数通常限制为 6 个。同时发起 8 个图片请求 + 1 个体素请求，会导致部分请求（如体素）被挂起。
3.  **日志不直观**: 缺乏类似 `occupancy_viewer` 的实时请求交互日志。

我将执行以下重构方案：

## 1. 服务端重构 (`server.py`)
*   **增加详细日志**: 仿照 `occupancy_viewer` 和标准 Web 服务器，输出包含时间、IP、请求路径、处理耗时的日志。
*   **性能优化**:
    *   **开启 `half_size=True`**: 在 `rawpy.postprocess` 中启用半分辨率解码。这会将解码速度提升 **4-5倍**，且对于 Web 预览（小窗口）画质几乎无损。
    *   **添加 LRU 缓存**: 使用 `@lru_cache` 缓存最近处理过的图片，避免重复计算。
    *   **显式多线程**: 确保 `app.run` 开启多线程模式。

## 2. 前端重构 (`viewer.js`)
*   **错峰加载 (Staggered Loading)**: 不再同时发起 8 个图片请求。改为每隔 50ms 加载一张，或优先加载体素，确保重要数据先显示，并防止浏览器网络堵塞。
*   **加载状态优化**: 增加图片加载失败的重试逻辑。

## 3. 预期效果
*   命令行将实时滚动显示每个请求的处理状态和耗时。
*   体素数据将优先或快速加载，不再转圈。
*   8 路相机画面将流畅显示（解码速度提升）。
