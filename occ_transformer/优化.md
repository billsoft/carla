### 一、你的 Nano 方案分析

#### 1.1 下采样链路核实

```
输入: [B, 8, 1, 960, 1280]
  ↓ Conv 7×7, s=4
[B, 8, 32, 240, 320]
  ↓ Conv 3×3, s=2  
[B, 8, 64, 120, 160]
  ↓ Conv 3×3, s=2
[B, 8, 128, 60, 80]
  ↓ Patch 8×8, s=8
[B, 8, 128, 7, 10]  →  每相机 70 patches

总下采样: 960→7 (137×), 1280→10 (128×)
每个 patch 覆盖原图 ~137×128 像素区域
```

#### 1.2 问题诊断

| 问题 | 严重程度 | 说明 |
|------|---------|------|
| **空间信息丢失过大** | ⚠️ 高 | 每 patch 覆盖 137×128 像素，行人/标志可能只占 1-2 像素 |
| **Bayer 特性未保留** | ⚠️ 中 | 直接用普通 Conv，没有 PixelUnshuffle 分离 RGGB |
| **BEV 25×25 太粗** | ⚠️ 中 | 50m 范围下每格 2m，定位精度受限 |
| **Encoder 2层太浅** | ⚠️ 中 | 跨相机关联不充分 |
| **通道 128 偏窄** | ⚠️ 低 | 18 类语义勉强够用 |

#### 1.3 核心矛盾

```
你的方案: 激进压缩空间 → 极短序列 → 省显存
问题:     丢失太多信息 → 精度下降严重

Transformer 的优势是全局建模，但前提是输入要有足够信息
如果输入已经被压缩到 7×10，Transformer 也救不回来
```

### 二、改进方案：Nano-V2

**核心思路**: 保留更多空间信息，用更聪明的方式压缩

#### 2.1 架构对比

| 配置 | 你的 Nano | **Nano-V2** | 说明 |
|------|----------|-------------|------|
| 前期下采样 | s=4,2,2 (32×) | s=2,2,2 (8×) | 保留更多空间 |
| Patch后分辨率 | 7×10 | 15×20 | 每相机 300 patches |
| 总 tokens | 560 | **2400** | 仍然很短 |
| embed_dim | 128 | **128** | 保持 |
| Encoder | 2层 标准Attn | **3层 窗口Attn** | 窗口避免O(N²) |
| BEV queries | 25×25=625 | **50×50=2500** | 分辨率翻倍 |
| Decoder | 1层 | **1层** | 够用 |
| Cross-Attn | 625×560=350K | 2500×2400=6M | 仍可接受 |
| 上采样 | 25→200 (8×) | 50→200 (4×) | 更容易 |

#### 2.2 Nano-V2 结构

```
输入: [B, 8, 1, 960, 1280]
  │
  ▼ Bayer 分离 (保留)
┌─────────────────────────────────────────────────┐
│ PixelUnshuffle(2)                               │
│ [B, 8, 1, 960, 1280] → [B, 8, 4, 480, 640]     │
│ 保留 RGGB 色彩信息                              │
└─────────────────────────────────────────────────┘
  │
  ▼ 温和下采样 (3层 CNN)
┌─────────────────────────────────────────────────┐
│ Conv 3×3, s=2, ch=32  → [B, 8, 32, 240, 320]   │
│ Conv 3×3, s=2, ch=64  → [B, 8, 64, 120, 160]   │
│ Conv 3×3, s=2, ch=128 → [B, 8, 128, 60, 80]    │
│ 总下采样: 8× (相比你的32×)                      │
└─────────────────────────────────────────────────┘
  │
  ▼ Patch Embedding
┌─────────────────────────────────────────────────┐
│ Conv 4×4, s=4, ch=128                           │
│ [B, 8, 128, 60, 80] → [B, 8, 128, 15, 20]      │
│ 每相机: 15×20 = 300 patches                     │
│ 总序列: 8 × 300 = 2400 tokens                   │
└─────────────────────────────────────────────────┘
  │
  ▼ 简化 Position Encoding
┌─────────────────────────────────────────────────┐
│ 2D Learnable PE: [300, 128]                     │
│ Camera ID Embed: [8, 128]                       │
│ 相加即可，省去复杂的射线计算                     │
└─────────────────────────────────────────────────┘
  │
  ▼ Encoder (窗口注意力)
┌─────────────────────────────────────────────────┐
│ 3层 Window Attention                            │
│ window_size = 5×5                               │
│ 每相机独立处理，最后一层跨相机                   │
│ 复杂度: 2400 × 25 = 60K (而非 2400² = 5.76M)   │
└─────────────────────────────────────────────────┘
  │
  ▼ BEV Queries
┌─────────────────────────────────────────────────┐
│ Learnable: [50×50, 128] = [2500, 128]          │
│ 每格 1m×1m (50m 感知范围)                       │
└─────────────────────────────────────────────────┘
  │
  ▼ Decoder (单层 Cross-Attention)
┌─────────────────────────────────────────────────┐
│ Cross-Attn: 2500 queries × 2400 keys           │
│ 复杂度: 6M (可接受)                             │
│ 或用 Deformable (K=4): 2500×4 = 10K            │
└─────────────────────────────────────────────────┘
  │
  ▼ BEV → 3D 扩展
┌─────────────────────────────────────────────────┐
│ Height MLP: [2500, 128] → [2500, 128×4]        │
│ Reshape: [50, 50, 4, 128]                       │
└─────────────────────────────────────────────────┘
  │
  ▼ 渐进上采样 (轻量)
┌─────────────────────────────────────────────────┐
│ BEV: 50→100 (PixelShuffle) → 200 (双线性)      │
│ Height: 4→16 (线性插值)                         │
│ 通道: 128→64→18                                 │
└─────────────────────────────────────────────────┘
  │
  ▼
输出: [B, 18, 200, 200, 16]
```

### 三、显存估算对比

#### 3.1 详细估算 (BS=1, FP16)

| 组件 | 你的 Nano | Nano-V2 |
|------|----------|---------|
| **CNN 下采样** | | |
| 激活值 | 8×32×240×320×2 + ... ≈ 50MB | 8×32×240×320×2 + ... ≈ 80MB |
| **Patch Tokens** | | |
| 序列 | 560×128×2 = 0.14MB | 2400×128×2 = 0.6MB |
| **Encoder** | | |
| 2层 Self-Attn 激活 | 560²×2×2×2 ≈ 2.5MB | 2400×25×3×2 ≈ 0.4MB (窗口) |
| FFN 激活 | 560×256×2×2 ≈ 0.6MB | 2400×256×3×2 ≈ 3.7MB |
| **Queries** | | |
| BEV | 625×128×2 = 0.16MB | 2500×128×2 = 0.64MB |
| **Decoder Cross-Attn** | | |
| 注意力矩阵 | 625×560×2 = 0.7MB | 2500×2400×2 = 12MB |
| **3D 特征** | | |
| 上采样前 | 25×25×4×128×2 = 0.6MB | 50×50×4×128×2 = 2.5MB |
| 上采样后 | 200×200×16×32×2 = 40MB | 200×200×16×64×2 = 80MB |
| **参数** | ~3M×2 = 6MB | ~5M×2 = 10MB |
| **梯度** | ≈ 激活值 | ≈ 激活值 |
| | | |
| **训练总计** | **~200-300MB** | **~400-500MB** |
| **推理总计** | **~100MB** | **~200MB** |

### 四、最终建议

#### 4.1 根据你的 24GB 显存

| 方案 | 训练显存 | 推荐场景 |
|------|---------|---------|
| 你的 Nano | ~300MB | ❌ 精度损失太大 |
| **Nano-V2** | ~500MB | ✅ **推荐** |
| Nano-V2 + 梯度检查点 | ~350MB | ✅ 显存紧张时 |
| Mini (50×50 BEV, dim=192) | ~1.5GB | ✅ 有余量时 |

#### 4.2 关键改动总结

```
你的方案问题:
1. 下采样 32× 太激进 → 改成 8×
2. 没有 Bayer 分离 → 加 PixelUnshuffle
3. 7×10 patches 太少 → 改成 15×20
4. 25×25 BEV 太粗 → 改成 50×50
5. 标准 Attention → 换成窗口 Attention

核心原则:
- 空间信息在前期尽量保留
- 序列长度用窗口注意力控制
- BEV 分辨率决定定位精度下限
```

#### 4.3 精度-效率权衡曲线

```
显存占用 (训练, BS=1)
    │
 2GB├──────────────────────● Standard
    │                    ╱
    │                  ╱
 1GB├────────────────●─── Mini

    │            ╱
0.5GB├──────────●───────── Nano-V2 (推荐)
    │        ╱

    │

        10%  20%  30%  40%
```

**结论**: 你的 Nano 方案压缩过度，建议采用 Nano-V2，在 24GB 显存下绰绰有余，同时保持合理精度。
