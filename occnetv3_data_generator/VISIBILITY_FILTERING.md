# 可见性过滤 (Visibility Filtering) 说明文档

本项目采用了 **基于语义激光雷达 (Semantic LiDAR) 的实例级可见性过滤** 机制，旨在生成与相机感知一致的 Occupancy Ground Truth。

## 1. 核心原理

为了确保 Dataset 中的 Ground Truth 体素仅包含相机可见的物体（以及被遮挡但属于同一实例的完整物体），我们引入了一个虚拟的语义激光雷达传感器。

### 1.1 传感器配置

*   **类型**: `sensor.lidar.ray_cast_semantic`
*   **位置**: 车辆中心，高度 **Z=1.8m**。
    *   *设计考量*: 尽量接近 8 个相机的中心高度（约 1.4m - 1.7m），同时必须高于车顶（Tesla Model 3 车高约 1.44m），以实现 360 度无遮挡视野，模拟 "透视自车" 的效果。
*   **水平 FOV**: **360 度** (全向覆盖)。
*   **垂直 FOV**: **90 度** (+45° ~ -45°)。
    *   *设计考量*: 覆盖大部分相机的垂直视野，同时保持高密度扫描。
*   **分辨率**: 256 线，200 万点/秒 (高密度，确保远距离物体能被击中)。

## 2. 过滤逻辑

过滤过程发生在体素生成之后，分为以下几个步骤：

### 第一步：获取可见 Actor ID

1.  **LiDAR 射线检测**: LiDAR 向四周发射射线。
2.  **命中判定**: 如果射线击中某个物体，获取该物体的 **Actor ID**。
3.  **ID 集合**: 将所有被击中物体的 Actor ID 加入 `visible_actor_ids` 列表。
4.  **强制保留 Ego**: 自车 (Hero Vehicle) 的 ID 始终被加入该列表，确保自车永远可见（即使 LiDAR 安装位置导致自车部分未被击中）。

### 第二步：体素过滤

遍历整个体素网格 (512x512x40)，根据体素的属性决定是否保留：

1.  **地面/地表保护 (Ground Protection)**:
    *   如果体素的语义标签属于 **地面类** (Road, Sidewalk, Terrain, RoadLine 等)，**无条件保留**。
    *   对应代码中的 `GROUND_LABELS = [11, 12, 13, 14, 6]`。
    *   这确保了路面、人行道等永远不会因为 LiDAR 扫描盲区而被错误过滤。

2.  **实例级保留 (Instance-based Retention)**:
    *   如果体素所属的 **Actor ID** 在 `visible_actor_ids` 列表中，**该 Actor 的所有体素均被保留**。
    *   *意义*: 只要物体表面被 LiDAR 扫到一点，整个物体（包括内部和背面）都会被保留。这避免了空洞化 (Hollow) 现象，符合 Occupancy 任务中 "完整物体" 的定义。

3.  **剔除不可见物体**:
    *   既不是地面，其 Actor ID 也不在可见列表中的体素，将被置为 **0 (Empty)**。
    *   这通常清除了被高墙、其他车辆完全遮挡的物体，以及地下的噪声。

## 4. 常见问题 (FAQ)

**Q: 为什么 LiDAR 安装在 Z=1.8m 而不是车内？**
A: CARLA 的 LiDAR 传感器是物理模拟的，如果安装在车内，射线会被车体遮挡，导致无法探测外部环境。为了模拟 "透视自车" 并获得 360 度视野，我们将传感器放置在略高于车顶的位置。

**Q: 远处的车辆会被过滤吗？**
A: 我们配置了高密度 (256线) 和长距离 (100m) 的 LiDAR。只要车辆在相机可见范围内且未被完全遮挡，通常都能被击中并保留。

**Q: 为什么地面没有被过滤？**
A: 我们使用了语义标签白名单 (`GROUND_LABELS`)，强制保留所有地面体素，不依赖 LiDAR 探测。
