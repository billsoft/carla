# 地面90度旋转变形根因分析与修复方案

## 🐛 问题现象

### 症状描述
1. **动态物体（车辆、树木、建筑）**: 随车辆转弯正常加载，位置准确 ✅
2. **地面**: 车辆完成第一个90度转弯后发生变形 ❌
3. **地面**: 车辆完成第二个90度转弯后再次变形 ❌
4. **变形表现**:
   - 地面错位（道路/人行道位置不对）
   - Index 超限导致加载失败
   - 地面出现空洞或重叠

### 关键观察
用户的核心洞察：
> "如果同样是坐标转换，为什么地面上的 actor 没有这个问题？地面很明显。"

这说明**坐标转换本身没问题**，问题出在**地面生成的特殊逻辑**上。

---

## 🔍 根因分析

### 坐标系统回顾

```
世界坐标系 (World Frame)
↕ grid_to_world_matrix (包含旋转!)
体素网格坐标系 (Ego Frame)
  - 原点: Ego 车辆中心
  - X轴: 车辆前方
  - Y轴: 车辆右侧
  - Z轴: 垂直向上
```

**关键**: `grid_to_world_matrix` **包含车辆的旋转**（yaw角度）！

### Actor 填充的正确流程（无问题）

**文件**: `ground_truth_voxel_generator.py:447-672` (`_fill_actor_bb`)

```python
# 1. Actor 在世界坐标系的 BBox
bb = actor.bounding_box
actor_transform = actor.get_transform()

# 2. 世界 → 网格坐标转换
world_to_grid_matrix = np.linalg.inv(grid_to_world_matrix)  # ✅ 包含旋转的逆矩阵
verts_world = bb.get_world_vertices(actor_transform)
verts_grid = world_to_grid_matrix @ verts_world

# 3. 计算网格索引
min_ix = floor((min(verts_grid[0]) - x_range[0]) / resolution)
max_ix = ceil((max(verts_grid[0]) - x_range[0]) / resolution)
...

# 4. 填充体素
occupancy[min_ix:max_ix, min_iy:max_iy, min_iz:max_iz] = label
```

**为什么 Actor 没问题？**
- 使用**完整的 4x4 变换矩阵**（包含旋转）
- 世界坐标 → 网格坐标的转换**包含了车辆旋转的补偿**
- 无论车辆如何旋转，Actor 总是正确映射到**以车辆为中心的网格**

### 🔴 根本问题：索引与坐标的错误对应

#### 问题核心

```python

# gv_x[i, j] 表示:
#   - 网格位置 (i, j)
#   - Ego Frame 坐标 (gx_range[i], gy_range[j])

j = k % 512   # Y 索引
```

**等等，索引没问题？** 让我重新分析...

## ✅ 正确的逻辑应该是

### 方案 A: 完全移除 Cache（最简单，但慢）

```python
# 直接对每个网格点查询
for ix in range(512):
    for iy in range(512):
        # 网格坐标
        gx = ix * res + x_min + res/2
        gy = iy * res + y_min + res/2

        # 网格 → 世界
        wx, wy, wz, _ = [gx, gy, 0, 1] @ grid_to_world_matrix.T

        # 查询

        # 直接填充

```

**优点**: 简单、正确
**缺点**: 262144 次 `get_waypoint` 调用，非常慢（~10秒）

### 方案 B: 使用世界坐标Cache，但正确映射（推荐）

**关键**: Cache 存储的是**世界坐标**的查询结果，但填充时要**根据世界坐标**反查网格索引。

```python
# 步骤 1: 建立世界坐标 → 网格索引的映射
world_to_grid_map = {}  # { (wx_key, wy_key): [(ix, iy), ...] }

for ix in range(512):
    for iy in range(512):
        gx = ix * res + x_min + res/2
        gy = iy * res + y_min + res/2

        wx, wy, _, _ = [gx, gy, 0, 1] @ grid_to_world_matrix.T

        # 世界坐标取整作为 key
        wx_key = int(floor(wx / cache_res))
        wy_key = int(floor(wy / cache_res))

        if (wx_key, wy_key) not in world_to_grid_map:
            world_to_grid_map[(wx_key, wy_key)] = []
        world_to_grid_map[(wx_key, wy_key)].append((ix, iy))

# 步骤 2: 查询世界坐标
for (wx_key, wy_key) in unique_keys:
    wx = (wx_key + 0.5) * cache_res
    wy = (wy_key + 0.5) * cache_res

    wp = map.get_waypoint(Location(wx, wy, 0))
    label = classify(wp)
    z = wp.transform.location.z

    cache[(wx_key, wy_key)] = {'label': label, 'z': z}

# 步骤 3: 填充网格（使用映射表）
for (wx_key, wy_key), data in cache.items():
    grid_cells = world_to_grid_map.get((wx_key, wy_key), [])

    for (ix, iy) in grid_cells:
        iz = calculate_z_index(data['z'], ego_location.z)
        if 0 <= iz < grid_size[2]:
            occupancy[ix, iy, iz] = data['label']
```

**优点**: 正确处理旋转，查询次数少
**缺点**: 需要额外的映射表

### 方案 C: 直接使用网格索引Cache（最高效）

**关键洞察**: Cache 应该以**网格索引**为 Key，而不是世界坐标！

```python
# 步骤 1: 对每个网格点查询（第一次）
for ix in range(512):
    for iy in range(512):
        key = (ix, iy)  # ✅ 使用网格索引作为 Key

        if key not in grid_cache:
            # 计算世界坐标
            gx = ix * res + x_min + res/2
            gy = iy * res + y_min + res/2
            wx, wy, _, _ = [gx, gy, 0, 1] @ grid_to_world_matrix.T

            # 查询
            wp = map.get_waypoint(Location(wx, wy, 0))
            label = classify(wp)
            z = wp.transform.location.z

            grid_cache[key] = {'label': label, 'z': z}

        # 填充
        data = grid_cache[key]
        iz = calculate_z_index(data['z'], ego_location.z)
        if 0 <= iz < grid_size[2]:
            occupancy[ix, iy, iz] = data['label']
```

**优点**: 最简单、最高效
**缺点**: Cache 无法跨帧复用（车辆移动/旋转后，网格对应的世界坐标改变）

---

## 🎯 推荐修复方案：**方案 C（网格索引Cache）+ 清除旧Cache**

由于体素网格是 Ego-Aligned（随车辆旋转），每帧的网格索引对应的世界坐标都不同，因此：

**修复策略**:
1. **每帧清空 Cache**
2. **使用网格索引 (ix, iy) 作为 Cache Key**
3. **直接填充到对应的网格索引**

这样既简单又高效，且完全正确！

---

## 🎓 为什么 Actor 没问题而地面有问题？

### Actor 填充的特点
- **使用完整的 4x4 变换矩阵**（包含旋转）
- **一次性转换**：世界坐标 → 网格坐标
- **无 Cache**：每个 Actor 实时计算
- **结果**：与车辆旋转角度无关，总是正确

### 地面填充的特点（修复前）
- **两次转换**：网格 → 世界 → Cache → 网格
- **使用 Cache**：世界坐标作为 Key
- **关键错误**：Cache Key（世界坐标）与填充目标（网格索引）不匹配
- **结果**：车辆旋转后，Cache 映射错误，导致地面变形

---

## ✅ 修复后的完整流程

```
1. 清空 Cache (每帧)
   ↓
2. 遍历所有网格索引 (ix, iy)
   ↓
3. 网格索引 → 网格坐标 (gx, gy)
   ↓
4. 网格坐标 → 世界坐标 (wx, wy) [包含旋转]
   ↓
5. 查询 Map API: (wx, wy) → label, z
   ↓
6. Cache[(ix, iy)] = {label, z}  ← 网格索引作为 Key
   ↓
7. 直接填充: occupancy[ix, iy, iz] = label
```

**关键**: Cache Key 与填充目标完全一致，避免任何映射错误！
