# 体素闪烁问题诊断与修复方案

## 问题描述

**现象**: 物体在连续帧之间出现**闪烁**行为
- **帧 N**: 物体存在 ✅
- **帧 N+1**: 物体消失 ❌
- **帧 N+2**: 物体再次出现 ✅

**影响**: 数据集质量低下,训练出的模型会产生不稳定的预测,严重影响自动驾驶安全性。

---

## 根本原因分析

### 原因 1: **体素采样不足 (Padding 不足以覆盖旋转体素)** ⭐⭐⭐ **确认根因**

#### 几何推导
当前实现使用了 `padding = 0.6 * resolution` (约 0.12m)。
然而，体素是立方体。当体素相对于 Actor 旋转时，**体素中心到体素顶点的最大距离**是：
$$ d_{max} = \frac{\sqrt{3}}{2} \times resolution \approx 0.866 \times 0.2m \approx 0.173m $$

**缺口计算**:
$$ Gap = 0.173m - 0.12m = 0.053m $$

这意味着，如果物体（如细杆）恰好位于体素的角落，距离中心 **0.12m ~ 0.17m** 之间：
1. **真实情况**: 体素的角点已经插入物体内部 → **应该被选中**。
2. **当前代码**: 中心点距离物体 > 0.12m (Padding) → **判定为未命中**。

这就是闪烁的来源：当物体移动时，它在“中心命中区”和“角落命中区（盲区）”之间切换。

### 原因 2: **深度过滤容差固定**
当前 `0.5m` 的容差在近处足够，但在远处（深度值 > 30m）可能因为 Z-buffer 精度或像素量化误差而变得边缘化。

---

## 修复方案

### 方案 A: **多点采样 (9-Point Sampling)** ⭐⭐⭐⭐⭐ **最终方案**

为了彻底解决几何漏检，我们将实现用户建议的 **多点采样策略**，并进行向量化优化以保证性能。

**逻辑**:
对于每个候选体素，我们检测 9 个点：
1. **中心点** $(0, 0, 0)$
2. **8 个顶点** $(\pm r/2, \pm r/2, \pm r/2)$

**判定**:
$$ IsOccupied = Check(Center) \lor Check(Corner_1) \lor ... \lor Check(Corner_8) $$

**优化**:
只对 **细小物体** (Pole, Sign, Pedestrian, Bike) 启用 9 点采样。大物体（车辆）保持中心采样以节省性能。

### 方案 B: **自适应深度容差**

$$ Tolerance = 0.5 + 0.02 \times Depth $$
例如：
- 10m 处: 0.7m
- 50m 处: 1.5m
这能有效抑制远处的深度噪声闪烁。

---

### 方案 C: **静态物体实例补全** (辅助方案)

#### 修改 `visibility_filter.py` Line 149

**当前代码**:
```python
unique_visible_ids = unique_visible_ids[unique_visible_ids != 0]  # 排除 0
```

**问题**: 静态物体 ID < 0 被排除,无法享受实例补全

**改进代码**:
```python
# 包含静态物体 (ID < 0) 和动态物体 (ID > 0)
# 只排除 ID=0 (空气/地面虚拟ID)
EXCLUDED_VIRTUAL_IDS = [0, -1011, -1012, -1013]  # 地面类虚拟ID不补全
unique_visible_ids = unique_visible_ids[~np.isin(unique_visible_ids, EXCLUDED_VIRTUAL_IDS)]
```

**效果**: 杆子、标志等静态小物体也能享受实例补全,进一步减少闪烁

```python

python dense_occupancy_collection/main_data_collection.py --frames 100

# 分析脚本
import numpy as np
from pathlib import Path

dataset_path = Path('dataset_output/occupancy')
frames = sorted(dataset_path.glob('*.npz'))

# 统计每帧的行人/杆子体素数
pedestrian_counts = []
pole_counts = []

for f in frames:
    data = np.load(f)
    occ = data['occupancy']
    actor_ids = data['actor_ids']

    # 统计行人 (Label 7)
    pedestrian_counts.append(np.sum(occ == 7))

    # 统计静态杆子 (ID < -10000, Label 15)
    pole_mask = (actor_ids < -10000) & (occ == 15)
    pole_counts.append(np.sum(pole_mask))

# 检测闪烁 (连续帧体素数骤变 >50%)
ped_diffs = np.abs(np.diff(pedestrian_counts))
pole_diffs = np.abs(np.diff(pole_counts))

ped_flicker_frames = np.where(ped_diffs > 0.5 * np.mean(pedestrian_counts))[0]
pole_flicker_frames = np.where(pole_diffs > 0.5 * np.mean(pole_counts))[0]

print(f"行人闪烁帧数: {len(ped_flicker_frames)} / {len(frames)-1}")
print(f"杆子闪烁帧数: {len(pole_flicker_frames)} / {len(frames)-1}")

if len(ped_flicker_frames) == 0 and len(pole_flicker_frames) == 0:
    print("✅ 无闪烁问题,修复成功!")
else:
    print(f"⚠️ 仍有闪烁,需进一步调试")
    print(f"  行人闪烁帧: {ped_flicker_frames[:10]}")
    print(f"  杆子闪烁帧: {pole_flicker_frames[:10]}")
```

**判断标准**:
- ✅ 闪烁率 < 5% (可接受)
- ❌ 闪烁率 > 20% (需进一步优化)

## 附加说明

### 为什么不用更密集的网格?

**方案**: 将分辨率从 0.2m 提升到 0.1m?

**问题**:
1. **体素数量暴增**: 512³ → 1024³ = **8 倍** 显存和计算量
2. **训练难度增加**: 模型参数量显著增大
3. **收益递减**: 0.2m 对自动驾驶已经足够精细

**结论**: 优化算法比增加分辨率更高效

### 为什么不用实例分割?

**方案**: 先检测物体,再填充完整实例?

**问题**:
1. **依赖检测器精度**: CARLA API 提供的 BBox 本身就是 Ground Truth
2. **复杂度增加**: 需要额外的分割模型
3. **实时性差**: 推理速度慢

**结论**: 保守光栅化是更好的平衡点

## 总结

**核心问题**: 单点采样 + 浮点精度 → 细小物体随机漏检 → 闪烁

**根本解决**: 多点采样 (中心 + 8 顶点) → 容错性强 → 稳定

**辅助优化**: 自适应容差 + 静态补全 → 进一步减少边界抖动

**预期改善**: 闪烁率从 40-60% 降低到 <5%

**实施难度**: 中等 (约 4-5 小时)

**性能影响**: <10% (可接受)
