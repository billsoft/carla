## 🐛 问题清单

### 问题 1: 地面条纹闪烁

**现象**: 地面出现横向条纹,像栅栏一样闪烁

**根因**:
- Cache 分辨率 `cache_res = 1.0m` 太大
- 导致 5×5 个体素 (每个 0.2m) 共享同一个 Cache Cell
- 所有体素使用相同的 Z 高度,产生"台阶"效应

**影响**:
- 地面不平滑
- 道路边界有锯齿
- 人行道、草地过渡不自然

---

### 问题 2: 90度旋转后地面变形

**现象**: 车辆旋转 90°/180°/270° 后:
- 地面类型错位 (Road 变成 Sidewalk)
- Index 超限崩溃
- 地面严重变形

**根因**:
- 使用世界坐标 `(wx, wy)` 作为 Cache Key
- 体素网格是 Ego-Aligned (随车辆旋转)
- 旋转后,相同的网格索引 `(ix, iy)` 对应不同的世界坐标
- Cache Key 与填充目标不匹配,导致错误映射

**影响**:
- 严重影响数据质量
- 训练数据不一致
- 无法进行旋转增强

---

### 问题 3: 坡道地面丢失 ⭐ (新发现)

**现象**: 坡道、桥梁、起伏路面的地面体素被错误丢弃,出现空洞

**根因**:
- 强制限制地面高度必须在车辆当前位置 ±0.4m (iz_ground ± 2) 范围内
- Map API 查询到的坡道高度超出范围,被直接丢弃
- 代码实现与注释意图矛盾 (注释说"不限制 Z 层",代码却强制限制)

**影响**:
- 上坡/下坡路段地面消失
- 高架桥完全缺失
- 地下通道入口断裂
- 严重影响训练数据完整性

**发现者**: 用户代码审查

**修改后**:

```python
keys_x = np.arange(self.grid_size[0])  # [0, 1, 2, ..., 511]
keys_y = np.arange(self.grid_size[1])  # [0, 1, 2, ..., 511]

keys_x_grid, keys_y_grid = np.meshgrid(keys_x, keys_y, indexing='ij')

keys_y_flat = keys_y_grid.ravel()

# 计算对应的世界坐标 (仅用于查询 Map API)

gy_flat = keys_y_flat * self.resolution + self.y_range[0] + self.resolution/2.0

points_grid_h = np.stack([gx_flat, gy_flat, np.zeros(len(gx_flat)), np.ones(len(gx_flat))], axis=1)
points_world_h = points_grid_h @ grid_to_world_matrix.T
```

**效果**: Cache Key 与填充目标完全一致,避免坐标映射错误

## 💡 技术原理

### 为什么动态 Actor 没有问题?

**Actor 填充逻辑**:
```
世界坐标 → Ego Frame (使用 4x4 变换矩阵)
          → 网格索引 (ix, iy, iz)
          → 直接填充

特点:
✅ 使用完整的变换矩阵 (包含旋转)
✅ 直接转换,无 Cache
✅ 实时计算,无累积误差
✅ 结果与旋转角度无关
```

### 为什么地面之前有问题?

**地面填充逻辑 (修复前)**:
```
网格索引 (ix, iy) → Ego Frame (gx, gy)
                   → 世界坐标 (wx, wy) [包含旋转!]
                   → Cache Key = floor(wx/res), floor(wy/res)
                   → 查询 Map API
                   → Cache[(wx_key, wy_key)] = label
                   → 填充 occupancy[ix, iy, iz] = Cache[(wx_key, wy_key)]

问题:
❌ Cache Key 基于世界坐标
❌ 填充目标是网格索引
❌ 旋转后映射错误
```

### 修复后的逻辑

**地面填充逻辑 (修复后)**:
```
网格索引 (ix, iy) → Cache Key = (ix, iy)
                   → Ego Frame (gx, gy)
                   → 世界坐标 (wx, wy) [仅用于查询]
                   → 查询 Map API
                   → Cache[(ix, iy)] = label
                   → 填充 occupancy[ix, iy, iz] = Cache[(ix, iy)]

优点:
✅ Cache Key 与填充目标一致
✅ 无坐标映射误差
✅ 旋转后仍然正确
✅ 逻辑清晰,易于理解
```

## 🚀 性能分析

### 当前性能

- **每帧查询数量**: 512×512 = 262,144 个网格点
- **Cache 策略**: 每帧清空,全部重新查询
- **估计时间**: ~2-5 秒/帧 (取决于场景复杂度)

### 为什么每帧都要清空 Cache?

**原因**: 体素网格是 Ego-Aligned (随车辆旋转)

**示例**:
```
yaw=0°:   grid(10,0) → world(ego_x+2.0, ego_y)     → Road
yaw=90°:  grid(10,0) → world(ego_x, ego_y+2.0)     → Sidewalk (不同的世界位置!)

如果 Cache 不清空:
  - yaw=0°:  Cache[(10,0)] = Road
  - yaw=90°: Cache[(10,0)] 仍然是 Road (错误!)

每帧清空:
  - yaw=0°:  Cache[(10,0)] = Road
  - yaw=90°: Cache 清空, 重新查询 → Sidewalk ✅
```

### 可能的优化方向

如果性能不足,可以考虑:

1. **分块查询**: 只查询车辆周围一定范围 (例如 50m)
2. **多线程并行**: 使用 ThreadPoolExecutor 并行查询
3. **缓存复用**: 如果车辆仅平移 (不旋转),可以尝试保留 Cache

**注意**: 当前优先保证正确性,性能优化可以在验证成功后再考虑。
